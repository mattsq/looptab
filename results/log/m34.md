# M34 — Explorative Modeling (XM) vs the refinement loop

**Status: DONE.** Two-sided result, and the sides disagree for a reason that turns out to be the
whole point.

> **Headline.** Best-of-K exploration does exactly what it claims — it makes a model *commit to a
> mode* instead of blurring to the conditional mean — and on a genuinely multimodal target it does
> so **decisively, on a NON-recurrent net, beating the refinement loop at the loop's own game**
> (mode validity +0.36, coverage +0.42 for an exploring MLP over the deterministic `trm_mixer`,
> 8/0, p=.0078). **But the benefit is intrinsically GENERATIVE and does not bank into supervised
> prediction:** on real multi-label, where the model is scored against ONE label, exploration's
> only measurable effects are a significant *cost* to any single answer and a large *unusable*
> oracle gain. XM is not a substitute for the loop on a supervised metric; it is a different
> objective for a different question.

## 0. What XM is and why it belongs in this repo

Explorative Modeling (Gladstone, Ji, Du 2026, [arXiv 2607.27372](https://arxiv.org/abs/2607.27372),
[code](https://github.com/alexiglad/XM)) attacks **multimodality in the target**. Standard
flow/diffusion training pairs a random latent with a datapoint under an independent coupling;
because many `x` are consistent with one latent, the regression target is a conditional *mean* and
predictions blur — which is why generation gets factored into ~100 denoising steps. XM instead
factors the **training loop**: draw K latents, produce K candidates, score each against the
datapoint, backprop only the closest. Each candidate can commit to a different mode, so the number
of modes captured grows with K. The paper pitches exploration as a **third pretraining axis**
(beside params and data) and claims **end-to-end generation** — one forward pass instead of many.

That last claim is why this is on-thesis here rather than a curiosity. TRM refinement *is* a
multi-step factorization used to handle hard targets; XM says the objective can do that job in one
step. It is the rival explanation of the loop, and it agrees in spirit with §11.2 #7/#10 and
M24e/M30 (untied ≈ tied; the loop is dressed-up depth) — except XM offers a constructive
replacement rather than a null.

## 1. What was built

All knobs default OFF; the full pre-M34 suite reproduces bit-identically (303 tests green).

- **`models/explore.py` — `ExploreWrapper`.** Appends an `explore_noise_dim`-wide latent noise
  channel to X so ANY arm (`ff_matched`, flat `trm`, `trm_mixer`, untied stacks) becomes a
  conditional sampler `y = f(X, ε)` with no model-class changes. **Default noise = zeros**, so the
  committed `evaluate` path is a deterministic single forward — the headline metric stays
  comparable to every earlier milestone and can never silently become an oracle. Attribute access
  falls through to the wrapped model, so `readout` / `halt_head` / the
  `init_state`/`return_state`/`n_steps` API keep working.
- **`train/loop.py: train_explore`.** The XM step: K latents → K no-grad forwards → **per-EXAMPLE**
  argmin against `y` → ONE gradient step through the winning latents. Cost is K no-grad forwards +
  1 train step (≈3× a K=1 step at K=8), which is the paper's own accounting.
- **`eval/metrics.py`.** Sampled / oracle@K metrics **plus the collapse check**
  (`latent_sensitivity`, `distinct_predictions`): if the model learns to ignore ε these go to 0/1
  and best-of-K has degenerated into noisier ERM. That null had to be detectable for any of this to
  mean anything. (It never fired — see §3.)
- **`data/generators.py: make_ambiguous_converge` + `ambiguous_modes`; `eval/ambiguity.py`.** The
  missing regime, see §2.

**The single-knob discipline that makes the Δs readable:** every deterministic arm carries the SAME
latent channel at `explore_noise_std: 0.0`. Architecture and parameter count are therefore identical
across the K axis, so `Δ(K=8 − K=1)` is exploration and nothing else, and `Δ(K=1 − det)` isolates
"merely having a stochastic latent."

## 2. The multimodal task — `ambiguous_converge`

Every other generator in this suite is a **single-valued function of X**, so XM has nothing to
explore: best-of-K would degenerate into a noisier ERM with K× the compute. Running it there first
would have repeated the M18 mistake (crediting a mechanism for what is just more optimization).

`ambiguous_converge` supplies the missing regime while staying inside the structure the loop's
validated win lives in (§9.2: local-update, deep, hard-convergence CA fixed points). Draw `s0`, then
**hide** a contiguous block of `n_masked` cells (position fixed by `task_seed` — it is part of the
*function*); the input shows the sentinel `0.5` there. Several completions relax to **different** CA
fixed points, so the row's conditional target distribution is genuinely multimodal with a **known,
enumerable support**, and the label is drawn uniformly over the distinct modes.

Screened at rule 78 (the M9/M24/M33 anchor), w=24:

| `n_masked` | mean modes | every row ambiguous | non-convergent completions | marginal-argmax ("blur") is a valid mode |
|---|---|---|---|---|
| 2 | 1.9 | ✓ | 0 | — |
| 4 | 3.7 | ✓ | 0 | **35.4%** |
| 6 | 6.7 | ✓ | 0 | **37.6%** |

That last column is what makes the task discriminating: a perfect conditional-mean predictor emits
something that is not any valid fixed point in ~2/3 of rows.

**The metric argument, which is load-bearing.** With labels uniform over a row's mode set, accuracy
and EM **provably cannot** separate the hypotheses: a perfect mode-sampler and a deterministic
pick-one-mode model both score `E[1/n_modes]` (0.30 at `n_masked=4`, 0.17 at 6). So M34 reports:

- **`mode_validity`** — is the prediction a member of the enumerated mode set at all? *Commit vs
  blur.* The honest headline.
- **`mode_coverage`** — fraction of a row's modes produced over 8 latent draws. XM's central claim
  ("modes captured grows with exploration") as a directly measurable quantity — possible only
  because the mode set is enumerable, which is exactly what the paper's own image/video/language
  domains cannot offer.

Both are scored for **every** arm with the same draw budget; a deterministic arm simply repeats its
one answer, so its coverage is `validity / n_modes` by construction. Coverage must therefore be read
*jointly* with validity — a coverage rise is only interesting if validity does not fall.

The mode set is re-derived **from X alone** at eval time (the sentinel makes X self-describing), so
nothing extra is plumbed through the dataset, and generation-time and eval-time enumerations are
asserted equal in `tests/test_generators.py`.

## 3. Result A (m34b) — on a genuinely multimodal target, exploration wins big, and wins WITHOUT the loop

8 seeds, `w=24`, rule 78, 100 epochs, budget-clean (all arms within ±5% of `trm_mixer_det`).
`n_modes` ≈ 1.9 / 3.7 / 6.7.

**Per-arm `mode_validity` (mean ± std over 8 seeds):**

| arm | n_masked=2 | 4 | 6 |
|---|---|---|---|
| `trm_mixer_det` | 0.289 ± 0.056 | 0.324 ± 0.054 | 0.153 ± 0.036 |
| `trm_mixer_xm1` | 0.302 ± 0.033 | 0.338 ± 0.080 | 0.107 ± 0.051 |
| **`trm_mixer_xm8`** | **0.670 ± 0.052** | **0.665 ± 0.045** | **0.643 ± 0.029** |
| `ff_det` | 0.308 ± 0.026 | 0.337 ± 0.017 | 0.172 ± 0.022 |
| `ff_xm1` | 0.291 ± 0.025 | 0.332 ± 0.017 | 0.191 ± 0.020 |
| **`ff_xm8`** | **0.387 ± 0.022** | **0.448 ± 0.018** | **0.508 ± 0.017** |
| `trm_flat_det` | 0.424 ± 0.015 | 0.420 ± 0.034 | 0.160 ± 0.025 |

Read the rows: the deterministic arms *decay* as ambiguity grows (0.29→0.15 for the mixer) — they
blur, exactly as designed-for — while the exploring arms **hold flat at ~0.64–0.67**.

**The Δs (paired, 8 seeds; 8/0 ⇒ p=.0078, the maximum attainable):**

| Δ | metric | n_masked=2 | 4 | 6 |
|---|---|---|---|---|
| `trm_mixer_xm8 − trm_mixer_xm1` (exploration, single knob) | validity | +0.367, 8/0 | +0.327, 8/0 | +0.536, 8/0 |
| | coverage | +0.630, 8/0 | +0.584, 8/0 | +0.506, 8/0 |
| `ff_xm8 − ff_xm1` (exploration on the NON-recurrent control) | validity | +0.096, 8/0 | +0.115, 8/0 | +0.318, 8/0 |
| | coverage | +0.434, 8/0 | +0.414, 8/0 | +0.392, 8/0 |
| **`ff_xm8 − trm_mixer_det`** (**can exploration replace the loop?**) | validity | +0.099, 8/0 | +0.124, 8/0 | **+0.355, 8/0** |
| | coverage | +0.500, 8/0 | +0.462, 8/0 | **+0.422, 8/0** |
| `trm_mixer_xm8 − ff_xm8` (does the architecture still add?) | validity | +0.282, 8/0 | +0.217, 8/0 | +0.135, 8/0 |
| `trm_mixer_xm1 − trm_mixer_det` (the latent ALONE) | validity | +0.013, 4/4 ns | +0.014, 6/2 ns | −0.046, 1/7 ns |
| `trm_mixer_det − ff_det` (M24 mixer anchor, no exploration) | validity | −0.020, 3/5 ns | −0.013, 6/2 ns | −0.019, 4/4 ns |

Five readings, in order of how load-bearing they are:

1. **Exploration is the mechanism, not the latent.** `Δ(xm1 − det)` on validity is null in all three
   cells; `Δ(xm8 − xm1)` is +0.10…+0.54 at 8/0. Adding noise does nothing; *selecting over* it does
   everything. (Coverage rises slightly for xm1 — mechanical: 2 distinct answers instead of 1.)
2. **The mechanism is live, never collapsed.** `latent_sensitivity` 0.10–0.16 and
   `distinct_predictions` 5.8–6.2 of 8 draws for the K=8 arms, vs exactly 0.000/1.00 for every
   deterministic arm. The null this experiment was built to be able to detect did not fire.
3. **XM's thesis, confirmed here: an exploring FEEDFORWARD net beats the deterministic refinement
   loop**, +0.099 / +0.124 / **+0.355** validity (8/0 in every cell), and the margin **grows with
   ambiguity**. The objective does what the architecture was credited for.
4. **Architecture still contributes on top — but its share shrinks as ambiguity grows.**
   `Δ(trm_mixer_xm8 − ff_xm8)` validity +0.282 → +0.217 → +0.135. Exploration and the mixer are
   complementary, with exploration taking over as the target gets more multimodal.
5. **On THIS task the M24 mixer edge does not exist without exploration.** `Δ(trm_mixer_det −
   ff_det)` is null on validity in all three cells (and `trm_flat_det` is actually the best
   deterministic arm at `n_masked=2/4`). Reported plainly: constraint propagation cannot pick a mode
   when the input does not determine one, so §11.2 #7/#8's coupled-task mixer win does not
   automatically carry to the *ambiguous* version of the same family. It re-appears only once the
   objective supplies commitment (reading 4).

**The cost, stated honestly.** Exploration costs token accuracy: `Δ(xm8 − xm1)` on accuracy is
−0.004…−0.011, significant in 4 of 6 arm×cell combinations (e.g. `ff_xm8 − ff_xm1` at n_masked=2:
−0.011, 0/8, p=.0078). EM *rises* for the mixer (+0.070 / +0.054 / +0.048, mostly 8/0) because a
valid mode has a `1/n_modes` chance of being the drawn label while a blurred row scores 0 — but EM
is the metric §2 argues cannot adjudicate this, so it is reported as consistency, not evidence.

### 3a. The compute control (M18's lesson)

A K=8 step costs ≈3× a K=1 step, and `mode_validity` *does* improve with training (the 200-epoch
seed-0 probe reached `trm_mixer_det` 0.287 vs 0.153 at 100 epochs), so the gap must survive a
compute handicap to be attributed to exploration. Two controls:

- **Free 2× control (probe, seed 0, all three cells at 200 epochs):** K=1/det arms at 200 epochs
  reach validity 0.20–0.53 — still far below the K=8 arms' 0.67–0.80 at the same 200 epochs, and
  below the 100-epoch K=8 arms this run reports. The *gap* is stable across the epoch doubling
  (0.45 at 200ep vs 0.49 at 100ep).
- **Explicit 3× control (`m34b_ambiguous_3xep.yaml`, 8 seeds):** the two K=1 arms at 300 epochs on
  the hardest cell (`n_masked=6`), against the 100-epoch K=8 arms. <!--RESULT-3XEP-->

## 4. Result B (m34a) — on real multi-label, the same mechanism is unbankable

`yeast` (co-occurring labels) and `scene` (mutually exclusive), 10-fold CV, seeds = the 10 DISJOINT
folds (so the paired sign test is valid), 300 epochs, budget-clean. Micro/macro-F1 is the honest
headline per §11.2 #9.

| Δ | dataset | micro-F1 | sampled EM | **oracle@8 EM** |
|---|---|---|---|---|
| `ff_xm8 − ff_xm1` | yeast | +0.005, 5/5 ns | −0.007, 4/6 ns | **+0.090, 10/0, p=.002** |
| `trm_xm8 − trm_xm1` | yeast | +0.010, 7/3 ns | −0.002, 5/5 ns | **+0.104, 10/0, p=.002** |
| `ff_xm8 − ff_xm1` | scene | −0.007, 5/5 ns | **−0.065, 0/10, p=.002** | **+0.177, 10/0, p=.002** |
| `trm_xm8 − trm_xm1` | scene | −0.008, 3/7 ns | **−0.081, 0/10, p=.002** | **+0.138, 10/0, p=.002** |

The mechanism is just as live as in §3 (`latent_sensitivity` 0.08–0.10; 3.4 distinct label-sets per
8 draws on yeast, 2.0 on scene, vs exactly 1.00 deterministic). But the effect decomposes into:

- a **significant, large gain in the candidate SET** (oracle@8 EM +0.09…+0.18, 10/0, p=.002 on both
  datasets and both architectures), and
- a **significant COST to any single answer** on scene (−0.065 / −0.081 sampled EM, 0/10, p=.002),
  directionally the same and ns on yeast, and
- **a tie on every deterministic headline metric** (micro-F1, macro-F1, accuracy, EM).

That is precisely what "spread mass over the modes" should do, and it is why it does not pay here:
**a supervised metric scores you against ONE label, so a diverse candidate set with no
inference-time selector is worth exactly nothing.** In generative modeling any mode is a valid
sample, so commitment is free money; in supervised prediction it is a bet you only win `1/n_modes`
of the time. The +0.09…+0.18 oracle gain is real and unbankable.

Anchors replicate, i.e. this run reproduces the repo it is embedded in:

- leg-1 joint > binary-relevance: yeast EM +0.034 (9/0, p=.004), miF1 +0.031 (9/1, p=.021); scene
  10/0 p=.002 on every metric.
- §11.2 #9's modal-label-combo artifact, in its purest form: `trm_det − ff_det` on scene is EM
  +0.036 (10/0, p=.002) but micro-F1 −0.0003 (6/4, ns). It reproduces *under exploration* too
  (`trm_xm8 − ff_xm8`: EM +0.037 8/1 p=.039, miF1 +0.012 7/3 ns).

## 5. Verdict

**The dividing line is the METRIC's relationship to the mode set, not the architecture.** Exploration
buys mode commitment; whether that is worth anything depends on whether being *a* valid answer scores
you points:

| regime | is "a valid mode" rewarded? | XM verdict |
|---|---|---|
| `ambiguous_converge` (`mode_validity`) | yes | **large win, 8/0, and it beats the loop without any loop** |
| real multi-label (F1 / EM vs one label) | no | **null on the headline; measurable cost to a single answer; large unusable oracle gain** |

For the repo's own question — *does the refinement loop have a defensible advantage?* — M34 is
another chip off it, from a new direction. On the one task where whole-row commitment is measured
directly rather than through EM, **a param-matched feedforward net with an exploration objective
beats the tied refinement loop at commitment (+0.36 validity, 8/0)**, and the loop's architecture
contributes a shrinking minority share. This is the same conclusion as §11.2 #7/#10 (the loop is
architecture, not recurrence) reached with a constructive alternative rather than a null.

**Do not over-read it.** XM's headline claims (6.2× sample efficiency, 4.1× FLOP efficiency, 1.43
FID, end-to-end generation) are **generative** claims about a *pretraining* axis, and nothing here
tests them: no generative arm exists in this repo, the models are tiny CPU nets, and §3's win is on
a synthetic task built specifically to make mode commitment measurable. What M34 establishes is
narrower and, for this repo, more useful: **exploration is a real mechanism with a real cost, its
payoff is gated by the metric, and where it pays it does not need the loop.**

## 6. Scope, caveats, what is closed

- **Closed — do not re-run:** exploration on real multi-label classification (both datasets, both
  architectures, K=8; the headline is a clean tie with a significant single-answer cost). The
  collapse check rules out "it silently no-op'd."
- **Caveat — coverage is partly mechanical.** A deterministic arm's coverage is `validity/n_modes`
  by construction, so coverage Δs must be read jointly with validity Δs (both are reported, and both
  are 8/0 in the same direction, so the reading holds).
- **Caveat — one exploration hyper-parameter setting.** K∈{1,8}, σ=1.0, noise width = one channel
  per cell (24) / 8 for multi-label. No sweep over K or σ; XM reports monotone improvement in K, and
  M34 tests only that K=8 ≫ K=1.
- **Caveat — the K=1 arm is not the pre-M34 model.** It is a noise-conditioned model trained through
  `train_explore`. `Δ(xm1 − det)` is reported precisely so the extra ingredient is visible; it is
  null on validity and ns on the multi-label headlines.
- **Caveat — `mode_validity` rewards emitting a valid mode, not the right one.** That is deliberate
  (§2 shows EM cannot discriminate), but it means §3's win is a win *at commitment*, not at
  accuracy. Token accuracy in fact costs 0.4–1.1%.
- **Open, if anyone wants to continue:** (1) a **selector** — the oracle gap (+0.09…+0.18 EM on real
  data, +0.40…+0.63 on synthetic) is the size of the prize if a model could rank its own candidates,
  which is the honest bridge from XM to supervised prediction; (2) K and σ sweeps, to test XM's
  monotonicity claim on tabular; (3) forecasting, where futures are genuinely multimodal but MSE
  rewards the conditional mean — it needs a distributional metric (CRPS / best-of-K MSE) first,
  which would break comparability with M26/M30–M32 and so was deliberately left out of M34.
